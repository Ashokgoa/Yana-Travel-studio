# API Documentation

Interactive, always-current docs are generated by FastAPI:

- Swagger UI: http://localhost:8000/docs
- ReDoc: http://localhost:8000/redoc
- OpenAPI JSON: http://localhost:8000/openapi.json

Base path: `/api/v1`. JSON only. Browsers reach it through the frontend at `http://<host>:3000/api/v1` (Next.js forwards to the backend, which listens only on `127.0.0.1:8000`). The Swagger/ReDoc links work on this laptop only.

## Error format

Every non-2xx response returns:

```json
{ "error": "validation_error", "message": "Some fields are invalid.",
  "details": [{ "field": "email", "message": "value is not a valid email address" }] }
```

| `error` | HTTP | When |
|---|---|---|
| `validation_error` | 422 | Request body or query is invalid (`details` lists fields) |
| `domain_error` (or specific code) | 400/404/409 | Business rule violated |
| `http_error` | 4xx | Not found, method not allowed, … |
| `internal_error` | 500 | Unexpected failure (details in server log) |

## Authentication

All endpoints except `GET /health` and `POST /auth/login` need a signed-in user. Browsers use the HttpOnly `yana_session` cookie set by login (send requests with `credentials: "include"`); API clients may send `Authorization: Bearer <token>`. `401 not_authenticated` = sign in again; `403 forbidden` = role not allowed.

| Method | Path | Roles | Description |
|---|---|---|---|
| POST | `/auth/login` | public | Body `{email, password}`. Sets the session cookie, returns the user |
| POST | `/auth/logout` | any | Clears the cookie (204) |
| GET | `/auth/me` | any | Current user with role |

## Inventory (Phase 2)

Read: any signed-in user. Create/update/status: **admin only** (403 otherwise).

| Resource | Path | Filters (besides `q`, `active`, `page`, `page_size`) |
|---|---|---|
| Countries | `/inventory/countries` | `region` |
| Cities | `/inventory/cities` | `country_id` |
| Suppliers | `/inventory/suppliers` | `supplier_type`, `country_id` |
| Attractions | `/inventory/attractions` | `city_id`, `country_id`, `category`, `child_friendly=true` |
| Hotels | `/inventory/hotels` | `city_id`, `country_id`, `star_rating` |
| Restaurants | `/inventory/restaurants` | `city_id`, `country_id`, `vegetarian`/`jain`/`halal`/`vegan` `=true` (verified only) |
| Vehicles | `/inventory/vehicles` | `category_id`, `supplier_id` |

Each resource supports `GET /` (paged list), `GET /{id}`, `POST /`, `PUT /{id}`, `PATCH /{id}/status` `{is_active}`. Lists include `primary_image_url` when images exist. Duplicates return `409 duplicate`; unknown references `400 invalid_reference`; bad filter values `422 invalid_filter`.

Hotel extras: `POST|PUT|DELETE /inventory/hotels/{id}/room-types[/{room_type_id}]` and `/inventory/hotels/{id}/rates[/{rate_id}]` (a rate must reference a room type of the same hotel; deleting a room type deletes its rates). Each returns the full hotel.

Also: `GET /inventory/options` (vocabularies for forms: categories, interest tags, facilities, weekdays…) and `GET /inventory/vehicle-categories`.

## Image library (Phase 2)

| Method | Path | Roles | Description |
|---|---|---|---|
| GET | `/media?q=&category=&illustrative=` | any | Paged library with `usage_count`, `url`, `thumbnail_url` |
| POST | `/media/upload` (multipart: `file`, optional `entity_type`+`entity_id`, `category`, `description`, `source`, `is_illustrative`, `is_ai_generated`) | any; **admin** when linking to a record | Validates and processes the image; identical files are reused (`created: false`) |
| GET | `/media/{id}` | any | Details plus `usages` (where it's used) |
| PATCH | `/media/{id}` | admin | `description`, `alt_text`, `source`, `is_illustrative` (AI images stay illustrative) |
| POST | `/media/{id}/replace` (multipart `file`) | admin | New file, same links everywhere; URL changes (`?v=`) |
| DELETE | `/media/{id}` | admin | Deletes file, thumbnail and all links; promotes a new primary where needed |
| GET | `/media/{id}/file`, `/media/{id}/thumbnail` | any | Image bytes, cached as immutable (URL carries a content hash) |
| GET | `/media/gallery/{entity_type}/{entity_id}` | any | Ordered gallery of a record |
| POST | `/media/links` `{entity_type, entity_id, media_id, caption?}` | admin | Reuse a library image (409 if already linked) |
| DELETE | `/media/links/{link_id}` | admin | Remove from record (file stays in library) |
| POST | `/media/links/{link_id}/primary` | admin | Make primary |
| PUT | `/media/links/{link_id}/caption` | admin | Caption for that record |
| PUT | `/media/gallery/{entity_type}/{entity_id}/order` `{link_ids}` | admin | Reorder (must list every link once) |

Errors: `invalid_image` (422, not a real/allowed image), `file_too_large` (413), `duplicate_image` (409 on replace), `already_linked` (409).

### Customer requirements (Phase 3)

| Method | Path | Description |
|---|---|---|
| GET | `/enquiries/requirements/options` | Vocabularies (preferences, interests, hotel categories, room types, food, meals, transport, pace, flexibility, class) |
| GET | `/enquiries/{id}/requirements` | Saved requirements, or defaults pre-filled from the enquiry (`exists: false`). Always includes `total_days`, `total_nights`, `total_travellers`, `rooms_count`, `room_capacity`, `missing[]`, `warnings[]`, `is_complete` |
| PUT | `/enquiries/{id}/requirements` | Save (draft-friendly). Validates vocabularies, children's ages, date order, duplicate destinations, and that each city belongs to its country (`400 city_country_mismatch`). Syncs the enquiry summary; first save moves a *New* enquiry to *In Progress* |

### Itinerary builder (Phase 5)

Saved versions (incl. v1 *Generated*) are read-only; edits apply to the working copy and return the updated itinerary (409 `version_locked` otherwise).

| Method | Path | Description |
|---|---|---|
| GET | `/itineraries/{id}?version=N` | View a specific version |
| GET | `/itineraries/{id}/versions` | Versions, newest first (label, notes, locked, author, days, est. cost) |
| GET | `/itineraries/{id}/versions/compare?a=&b=` | Plain-English differences |
| POST | `/itineraries/{id}/edit` | Start editing (creates a working copy if needed) |
| POST | `/itineraries/{id}/versions` `{label, notes?}` | Save the working copy as a named read-only version |
| POST | `/itineraries/{id}/versions/{n}/restore` | Restore version n as a new working copy (an open draft is auto-saved first) |
| POST | `/itineraries/{id}/duplicate` | Copy the itinerary |
| POST | `/itineraries/{id}/days/{n}/add-after` · `/duplicate` | Add / duplicate a day |
| DELETE | `/itineraries/{id}/days/{n}` | Remove a day (not arrival/departure) |
| PATCH | `/itineraries/{id}/days/{n}` `{title, description}` | Edit day text |
| POST | `/itineraries/{id}/days/{n}/activities` | Add sightseeing (`attraction_id`) or free-time/custom activity |
| PATCH / DELETE | `/itineraries/{id}/activities/{aid}` | Edit / remove an activity |
| POST | `/itineraries/{id}/activities/{aid}/move` `{day_number, position, time_slot?}` | Move an activity |
| PUT | `/itineraries/{id}/days/{n}/meals/{breakfast\|lunch\|dinner}` `{arrangement, restaurant_id?}` | Set a meal |
| PUT | `/itineraries/{id}/stays/{sid}/hotel` `{hotel_id}` | Replace a hotel (same city; re-priced) |
| PUT | `/itineraries/{id}/vehicle` `{vehicle_id}` | Change the vehicle |
| PATCH | `/itineraries/{id}/transports/{tid}` `{mode}` | Change a leg's mode |

Every response re-runs the live checks and cost estimate.

Business-rule errors (400): `invalid_agent`, `inactive_agent`, `invalid_customer`, `customer_agent_mismatch`, `invalid_planner`.
